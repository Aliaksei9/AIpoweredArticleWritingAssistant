# Проверка качества кода VelesAI — 13.11.2026

Проверены все пять функциональных модулей, контроллер и UI: 62 Python-файла и 4 JavaScript-файла, а также схема и запрос обзора PostgreSQL, HTML/CSS и точки запуска. Основные критерии — оправданность классов, разделение ответственности, повторение логики, расширяемость, обработка ошибок и сохранение поведения.

Изменения ограничены подтверждёнными повторами. В рабочих модулях классы не добавлялись и не удалялись; новые числовые значения, специальная обработка конкретных статей или каналов не вводились. Добавлен один общий файл функций строгого разбора JSON. Результат проверки каждого файла указан в [reviewed_files.json](reviewed_files.json).

## Почему некоторые похожие конструкции сохранены

- `SourceAdapter`, `SourceRegistry`, `BDdataCollection` и классы таблиц нужны для добавления новых источников и сохранения единственного владельца записи в БД.
- Классы и методы старых социальных моделей поддерживают загрузку прежних joblib-файлов и режим `legacy`; ссылки на них остаются в исследовательских сценариях и тестах. Удаление сократило бы функциональность и совместимость.
- Проверка фактов и проверка грамматики по-разному обрабатывают частично корректные ответы: редакторский анализ требует итоговых рекомендаций ко всем предложениям, языковая проверка умеет возвращать подтверждённые правки вместе с предупреждением о непроверенных предложениях. Их повторы запросов не объединялись в универсальную машину состояний.
- Транзакции, сохранение отчётов при отмене и проверки границ текста сохранены. Даже одиночная операция в savepoint может изолировать SQL-ошибку от внешней транзакции.
- UTC-преобразование сборщика и строгое преобразование пользовательской даты имеют разные контракты: обработка наивной даты намеренно различается.
- PyTorch-архитектура, гиперпараметры, порядок кандидатов, префиксы/размерность SBERT, ранжирование примеров и ограничения контекста сохранены.

## Проверка сохранения поведения

Перед изменениями выполнены исходные 189 Python-тестов и сохранён снимок результатов всей выборки **11740 уникальных статей**. После изменений побитно совпали:

- метки формулы по социальным метрикам;
- выходы сохранённой текстовой нейросети;
- прогнозы трёх социальных метрик при фактическом возрасте счётчиков;
- прогнозы тех же трёх метрик на семь дней;
- fingerprint подготовленной обучающей выборки и хеш всех 3000 конфигураций реакций.

Отдельно сопоставлено AST функций подбора реакций после подстановки вынесенных констант: алгоритмы идентичны. SHA256 обоих рабочих артефактов сохранены. Это проверка эквивалентности рефакторинга, а не новый эксперимент по подбору моделей или оценке точности на седьмой день.

Итог: **195 Python-тестов**, **17 JavaScript-тестов**. Добавлены регрессионные проверки вложенных дублирующихся JSON-ключей/NaN/Infinity, настроек окружения, изоляции кэша между запросами и жизненного цикла общего LLM-клиента. Проверка импорта старых классов остаётся частью совместимости.

Реальный полный API-запрос с SBERT, оценкой текста и тремя социальными моделями прошёл. Максимальный прогретый ответ — **3.548 с**, включая тексты до 50 000 символов. Загрузка моделей и первый запрос исключены из ограничения 10 секунд. [Замеры](latency.json).

Проверка с реальным PostgreSQL прошла: повторный сбор обновляет одну строку, более старый набор метрик не перезаписывает свежий, таблицы истории нет. Временные статьи/ресурсы интеграционного теста полностью откатились. Для проверки был запущен установленный Docker Desktop; контейнер PostgreSQL исправен.

Ответы OpenRouter, повторные попытки, бесплатный fallback и некорректные JSON проверялись локальными транспортными/LLM-фикстурами; реальные запросы к внешним моделям в эту проверку не входят. [Машинный протокол](verification.json).

## Воспроизведение

```powershell
python -m unittest discover -s model_tests -p "test_*.py"
node --test model_tests/test_editor_state.mjs model_tests/test_language_state.mjs model_tests/test_language_ui.mjs model_tests/test_forecast_context.mjs
python -m model_tests.check_single_snapshot
```

`model_tests/verify_refactoring.py` сохраняет и сравнивает полные результаты (`--snapshot` перед изменениями, без флага после) с явными путями `--corpus`, `--scores`, `--text`, `--social`, `--output`. Локальные статьи, матрицы и контрольные прогнозы в GitHub не включены.
