# Общие входы социальных моделей

Для просмотров, реакций и комментариев используется один общий набор входов:

| Поле | Значение |
| --- | --- |
| `document_embedding` | SBERT-вектор полного текста |
| `topic` | Тема публикации |
| `score` | Прогнозная оценка популярности модуля 3 |
| `resource_id` | Идентификатор ресурса |
| `source` | Тип источника, сейчас TG |
| `audience` | Аудитория выбранного ресурса |
| `published_at` | Планируемое время публикации с часовым поясом |

Прогноз просмотров, реакций и комментариев всегда рассчитывается **на 7-й день после публикации**. Срок не задаётся пользователем, не передаётся в API и не является параметром команды прогнозирования. Время публикации по-прежнему можно указать; пустое значение означает сейчас.

Для совместимости с обученными весами во внутреннюю матрицу добавляется постоянное значение возраста 7 дней. При обучении используется фактический возраст имеющихся счётчиков (2–14 дней); он не подменяется семью днями.

`UnifiedFeatureEncoder` формирует полную матрицу один раз. Все три модели получают именно эту матрицу, без удаления темы, оценки текста или времени для отдельных счётчиков. Параметры и веса моделей подбираются независимо. Обучаемое влияние признаков может различаться.

Контроллер вычисляет вектор текста один раз для определения темы, модуля 3 и трёх социальных моделей. Модуль 3 по-прежнему получает только текст и тему.

## Одна текущая запись на статью

В БД остаются пять исходных таблиц. У `article_metrics` первичный ключ — ID статьи. Повторный сбор обновляет существующие счётчики, аудиторию и `collected_at`; прежние значения не накапливаются. Запоздалый ответ не перезаписывает более свежие метрики.

Таблица `article_metric_observations`, сохранение прежних текстовых версий и подбор замера, ближайшего к седьмому дню, удалены. `init-db` удаляет прежнее расширение схемы. В текущем рабочем окружении миграция выполнена с сохранением всех 9283 актуальных статей, метрик и векторов; резервная копия оставлена локально.

Сохраняются дата публикации и время **последнего** сбора. По ним вычисляется возраст, которому соответствуют целевые счётчики. Срок пользовательского прогноза фиксирован: семь дней после публикации. Сбор по-прежнему ограничен возрастом 2–14 дней. `reembed` пересчитывает только актуальные тексты. `reset-db` очищает пять таблиц.

## Обучение

```powershell
python -m src.database init-db
python -m model_tests.validate_unified_metrics --database-only --output model_tests/results/my_unique_validation
python -m src.social_metrics_prediction train
```

Команда проверки использует всю доступную текущую выборку. В каждой статье ровно одна метка, полученная из последних метрик. Точные нормализованные повторы текста объединяются для разбиения. Оценки модуля 3 для обучения модуля 4 получаются вне обучающих групп через cross-fitting. Фактические счётчики прогнозируемой статьи не используются в признаках.

`train` по умолчанию использует `--feature-mode unified --text-strategy additive_ensemble`, сохраняет согласованную пару и SHA256 текстовой сети. После смены эмбеддингов или формулы целевой оценки обе модели следует переобучить. Старый режим `legacy` сохранён для чтения прежних статистических моделей; он также не хранит повторных замеров.

## Результат

Последняя полная проверка содержит 11740 уникальных статей из локального корпуса. Все прежние строки одного ID предварительно сведены к последней записи. Для прежних и новых социальных моделей использованы одинаковые разбиения и прогнозные оценки текста. После отдельного подбора реакций снижение MSE относительно среднего канала: просмотры 12.66%, реакции 1.57%, комментарии 1.93%. Веса просмотров, комментариев и текстовой сети сохранены. [Последний подбор реакций](experiments/2026-11-12-reactions/README.md); [внедрение общих входов](experiments/2026-11-12-unified-inputs/README.md).

Прогноз остаётся оценкой по наблюдаемым данным. Для проверки будущих дат нужен отдельный контроль; один текущий замер не описывает полную динамику роста счётчиков.
