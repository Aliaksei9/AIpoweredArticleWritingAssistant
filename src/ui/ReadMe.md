# VelesAI — редактор публикаций

Локальный интерфейс и контроллер связывают рабочие модули оценки текста, прогноза социальных метрик и корректировки текста.

## Запуск

Из корня `C:\4kurs\coursework`:

```powershell
# При первом запуске после обновления проекта
.\.venv312\Scripts\python.exe -m pip install -r requirements.txt

# Запустить PostgreSQL в Docker Desktop
docker compose up -d db

# Запустить редактор
.\start-ui.cmd
```

Открыть **http://127.0.0.1:8000/**. Терминал с сервером должен оставаться открытым; остановка — `Ctrl+C`.

Если порт 8000 уже занят ранее запущенным редактором, достаточно открыть этот адрес. Повторный запуск проверяет порт и выводит пояснение. Для отдельного экземпляра используйте `--port 8001` и адрес `http://127.0.0.1:8001/`.

Альтернативные команды:

```powershell
.\.venv312\Scripts\python.exe -m src.ui
.\.venv312\Scripts\python.exe main.py

# Если порт занят
.\start-ui.cmd --port 8001
```

Приложение использует `.env` в корне проекта. Для рекомендаций нужны заполненная БД, `DATABASE_URL` и `OPENROUTER_API_KEY`. Модель и ограничения OpenRouter задаются существующими `OPENROUTER_*`; по текущей конфигурации используется бесплатная `nvidia/nemotron-3.5-super-vl:free`.

Необязательные рассуждения модели по умолчанию отключены (`OPENROUTER_REASONING_ENABLED=false`). При временном отказе провайдера в бесплатном режиме используется резерв из `OPENROUTER_FALLBACK_MODELS`; фактическая модель записывается в ответ, а в UI появляется сообщение об использовании резерва. Таймаут, лимит запросов и ошибка проверки фактов отображаются с отдельными пояснениями.

Настройки интерфейса: `UI_PORT=8000`, `UI_MAX_EXAMPLES=5` — максимальное количество найденных популярных статей в контексте LLM. По умолчанию передаются пять полных примеров, если они найдены и помещаются в контекст. Значение можно увеличить. Итоговое количество примеров дополнительно ограничивает бюджет контекста модуля 5.

Статьи-примеры передаются только целиком. Если очередная статья не помещается, она пропускается, а число примеров уменьшается. Текст пользователя также передаётся полностью.

Порог близости содержательных примеров: `TEXT_CORRECTION_MIN_SIMILARITY=0.6` (диапазон `[-1; 1]`). Повышение порога делает подбор строже; при отсутствии совпадений используются лучшие статьи выбранной темы с предупреждением. Этот порог не ограничивает резервный подбор.

Рабочие артефакты загружаются один раз при первом подключении:

- `artifacts/text_models/neural_network.joblib`;
- `artifacts/social_metrics/model.joblib`;
- фиксированная `intfloat/multilingual-e5-small`, доступная в локальном кеше или для скачивания.

Контроллер проверяет согласованность пары моделей по SHA-256. Если артефактов нет или они не согласованы, сообщение в интерфейсе предложит команду `python -m src.social_metrics_prediction train`. Повторное обучение при обычном запуске не требуется. Первое подключение может занять время на загрузку моделей.

## Работа с текстом

1. Выберите канал и тему; тему можно определить автоматически.
2. Вставьте текст слева. Кнопка **«Обновить оценку соответствия»** вычисляет оценку `[-10; 10]`, просмотры, реакции и комментарии для текущего текста и выбранного канала.
3. Нажмите **«Найти улучшения»**. Модуль 5 найдёт похожие популярные статьи в PostgreSQL и передаст их вместе с текстом в OpenRouter. Карточки появятся после проверки JSON-ответа.
   Если похожих по содержанию статей нет, будут выбраны лучшие тексты выбранной темы; над карточками появится предупреждение. Если в БД нет и таких примеров, LLM даст общие редакторские рекомендации. Предупреждение видно уже во время ожидания ответа.
4. Выберите карточку: связанное предложение подсветится жёлтым. **«Принять»** заменяет только это предложение, **«Отклонить»** оставляет текст. **«Отменить»** возвращает предыдущее решение и текст.
5. После правок обновите оценку большой кнопкой снизу. Принятая редакторская рекомендация сама по себе не гарантирует роста оценки модели.

Оценка рассчитывается отдельно от запроса рекомендаций: ожидание LLM не блокирует локальное прогнозирование. Старый прогноз после изменения текста или параметров помечается как устаревший. Ручное редактирование отменяет текущий поиск и удаляет карточки прежней версии; запоздалый ответ не применяется. Изменение длины принятого предложения корректирует позиции следующих карточек, в том числе при наличии emoji.

Черновик, канал и выбранная тема сохраняются в `localStorage` этого браузера. Карточки и прогноз при перезагрузке запрашиваются заново. В БД черновики не записываются. Ключ OpenRouter остаётся на Python-сервере; текст отправляется в OpenRouter при нажатии кнопки поиска рекомендаций.

Без PostgreSQL локальный прогноз доступен по каталогу и аудитории каналов из артефакта модели; интерфейс явно сообщает об этом. Для RAG-рекомендаций требуется работающая БД. Кнопка обновления подключения справа сверху перечитывает каталог каналов.

## Устройство

| Компонент | Назначение |
| --- | --- |
| `src/controller/editor_controller.py` | Общий E5, определение темы, модель 3 → модель 4, RAG → LLM модуля 5 |
| `src/controller/correction_jobs.py` | Отменяемые фоновые задания рекомендаций; ограничение времени ожидания |
| `src/ui/app.py` | FastAPI, проверка входных данных, локальные HTTP-маршруты |
| `src/ui/__main__.py` | Uvicorn и совместимый с psycopg цикл событий Windows |
| `src/ui/static/` | Редактор, карточки, подсветка, прогноз; без сборки и внешних CDN |
| `model_tests/test_editor_controller.py` | Проверки API, контроллера, отмены, таймаутов и позиций предложений |
| `model_tests/test_editor_state.mjs` | Проверки применения правок, отклонения, отмены и UTF-16 |

Текст векторизуется один раз для вычисления оценки и автоматического определения темы. В модуль 4 передаются **предсказанная** оценка модуля 3, выбранный ресурс, `TG`, тот же вектор текста и время публикации. Прогноз всех трёх метрик всегда рассчитывается **на 7-й день после публикации**. Поля выбора срока нет; это явно указано в заголовке прогноза и подписи. Изменение текста или времени публикации делает прежний прогноз неактуальным. [Контракт и ограничения](../../docs/unified_social_inputs.md). Обучающие метрики имеют фактический возраст 2–14 дней; прогноз остаётся ориентировочным.

Карточка разделена на «Оценку текста» и «Прогноз социальных метрик через семь дней». Оценка имеет отдельную шкалу, три метрики показаны в одинаковых ячейках. До расчёта выводится подсказка, после изменения текста или даты — предложение обновить оценку. Поле «Планируемое время публикации» показывает «Сейчас» либо выбранные дату и время в русском формате; для ввода используется встроенный календарь браузера. При пустом поле API получает `published_at: null` и использует текущее время.

HTTP API:

- `GET /api/workspace` — темы, каналы и состояние подключений;
- `POST /api/predictions` — `{text, topic: null | string, resource_id, source: "TG", published_at: null | ISO8601}`; ответ содержит фиксированный срок `forecast.horizon_days: 7` и дату прогноза;
- `POST /api/corrections` — `{text, topic: null | string}`, возвращает `202` и ID задания;
- `GET /api/corrections/{id}` — статус и результат;
- `DELETE /api/corrections/{id}` — отмена задания.

Позиции предложений в HTTP-ответе передаются в UTF-16 для JavaScript. Исходный модуль 5 продолжает использовать позиции Python. Задания хранятся в памяти одного процесса: одновременно выполняется один запрос рекомендаций, история ограничена 20 заданиями и очищается при новых запросах спустя 30 минут. Сервер слушает только `127.0.0.1`.

### Орфография, пунктуация, грамматика и синтаксис

Кнопка «Проверить орфографию и пунктуацию» запускает независимый LLM-запрос.
Красным выделяются слова с орфографическими ошибками; синим — предложения с
пунктуационными, грамматическими или синтаксическими ошибками. Нажатие на фрагмент
открывает исправление с объяснением и кнопками «Применить» / «Пропустить».
При пересечении красной и синей подсветки появляются оба исправления. Есть
кнопка «Следующая ошибка» для перехода с клавиатуры, закрытие по Escape и отмена правки.

API: `POST /api/language-checks` с `{text}`, затем `GET /api/language-checks/{id}`;
`DELETE /api/language-checks/{id}` отменяет проверку. Это отдельная очередь: поиск
редакторских рекомендаций и проверка языка могут выполняться одновременно.
Проверка языка не требует PostgreSQL и загруженных моделей прогнозирования.

Если модель не смогла выдать проверяемые правки для части предложений даже после
повтора, остальные исправления остаются доступны. Над редактором появляется
предупреждение с номерами непроверенных предложений, а не сообщение об отсутствии ошибок.

После ручного редактирования результаты проверки сбрасываются; запоздавший ответ
не применяется. Языковые исправления сдвигают координаты оставшихся ошибок и
сохраняют независимые пунктуационные правки. После принятия языковой правки
рекомендации о популярности нужно запросить заново, а прогноз пересчитать.
Жёлтая подсветка редакторских рекомендаций сохраняется.

Все проверки находятся вне `src`, в `model_tests/`; команды приведены в `model_tests/ReadMe.md`.
