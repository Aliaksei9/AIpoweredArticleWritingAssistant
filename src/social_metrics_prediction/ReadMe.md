# Прогнозирование социальных метрик — модуль 4

`SocialMetricsPredictor` принимает **тему, оценку соответствия паттернам популярности, ресурс и вид ресурса**. Возвращает три неотрицательных целых числа: **просмотры, реакции, комментарии**.

В рабочей версии оставлена одна выбранная семья: **нейронная сеть MLP**. На каждую метрику обучается отдельная сеть. Градиентный бустинг, случайный лес, CatBoost и альтернативная MLP для сравнения находятся в `model_tests/social_metric_candidates.py`.

## Признаки и обучение

Тема, UUID ресурса и тип источника кодируются OneHotEncoder. Дополняют их оценка популярности, делённая на 10, и `log1p(аудитория)`. Аудитория берётся из свойств ресурса, отдельный обязательный аргумент пользователя для неё не нужен. Категории и scaler обучаются только на обучающих данных. Размер словаря сохраняется вместе с моделью.

Каждая сеть: `число признаков → 64 → 32 → 1`, ReLU, Adam, 300 эпох, batch 128, шаг 0.001, alpha 0.1. Реализация — `sklearn.neural_network.MLPRegressor`. StandardScaler отдельно масштабирует признаки и цель; оба scaler сохраняются. Валидационные и проверочные данные не используются для остановки обучения.

Цель обучения каждой сети — количество метрики на 1000 подписчиков. Вес наблюдения пропорционален квадрату аудитории: взвешенная квадратичная ошибка таких целей эквивалентна ошибке абсолютных количеств с точностью до общего множителя. Прогноз умножается на аудиторию / 1000, ограничивается снизу нулём и округляется. Просмотры не ограничиваются количеством подписчиков.

Для обучения используется **снимок аудитории конкретной статьи** `article_metrics.audience`. Для прогноза используется текущая аудитория ресурса из БД. При автономной работе можно использовать каталог из артефакта или передать `ResourceInfo` с обновлённой аудиторией.

## Оценка популярности без утечки ответов

Оценка модуля 2 зависит от просмотров, реакций и комментариев — целевых ответов модуля 4. Она используется только как **целевая метка обучения модуля 3**. В признаки модуля 4 поступает прогноз нейросети по тексту и теме.

При обучении модуля 4 эти прогнозы получают методом cross-fitting: для каждой статьи нейросеть обучается без её группы одинаковых текстов. Затем модуль 3 обучается на всех данных для рабочего прогноза. Команда `train` сохраняет согласованную пару и SHA256 артефакта модуля 3; при последовательном прогнозе CLI проверяет соответствие пары. После обновления БД переобучайте пару этой командой.

## Команды из корня проекта

```powershell
# Обучение выбранных моделей модулей 3 и 4 на всей размеченной БД
.\.venv312\Scripts\python.exe -m src.social_metrics_prediction train

# Каталог ресурсов: UUID, названия, аудитории, типы
.\.venv312\Scripts\python.exe -m src.social_metrics_prediction resources

# Прогноз с уже известной оценкой модуля 3
.\.venv312\Scripts\python.exe -m src.social_metrics_prediction predict --topic 'Игры' --score 2.5 --resource 'Jeteed' --source TG

# Последовательный прогноз: текст → модуль 3 → модуль 4 → социальные метрики
.\.venv312\Scripts\python.exe -m src.social_metrics_prediction predict --topic 'Технологии' --text-file model_tests/example_article.txt --resource 'Jeteed' --source TG
```

Ресурс задаётся UUID или точным названием из БД. Для `Jeteed` принимается также `@Jeteed`, поскольку название канала совпадает с username. Для остальных каналов username может отличаться от названия; используйте `resources` и UUID. При совпадающих названиях обязательно используйте UUID.

Артефакты по умолчанию: `artifacts/social_metrics/model.joblib` и `artifacts/text_models/neural_network.joblib`. Файл `model.training.json` содержит идентификаторы статей, разбиения, оценки вне обучающих групп, хэши и параметры обучения. `--output`, `--text-model-file`, `--folds`, `--threads`, `--seed` меняют параметры обучения. Команда прогнозирования поддерживает `--model-file`, `--text-model-file` и `--offline-resources`; последний использует аудиторию, сохранённую в модели, без обращения к БД.

Для обучения и обычного прогноза нужен PostgreSQL из Docker и `DATABASE_URL` в `.env`. Для `--text-file` нужен локальный кэш E5, настроенный через `HF_HOME`. Обучение и прогноз читают таблицы через классы модуля БД и сохраняют модели локально. Предсказанные количества не подменяют наблюдаемые значения в БД.

## Python API

```python
from src.social_metrics_prediction import SocialMetricsPredictor, ResourceInfo

model = SocialMetricsPredictor.load("artifacts/social_metrics/model.joblib")
result = model.predict("Игры", 2.5, "Jeteed", "TG")
print(result.to_dict())  # views, reactions, comments

# Обновление аудитории существующего ресурса без переобучения:
resource = ResourceInfo(
    id="fb4c1bf9-2542-54e4-baf5-73b4433599b1", name="Jeteed",
    audience=200000, source="TG",
)
result = model.predict("Игры", 2.5, resource, "TG")
```

Публичный `fit(rows, counts)` принимает подготовленные строки с прогнозными оценками; полный правильный процесс их получения реализован в `train`. `predict_rows(rows)` возвращает матрицу `(n, 3)` в порядке просмотры, реакции, комментарии. Загружайте собственные доверенные joblib-файлы.

## Источники и ограничения

Тип источника — общее строковое поле, а не Telegram-специфичный идентификатор. Сейчас обучающие данные есть только для `TG` (`Telegram`). Для VK/X потребуются соответствующий сборщик, данные и переобучение; модель явно отклоняет не представленный при обучении тип. Новая тема или ресурс TG кодируются с неизвестной категорией; для нового ресурса нужен `ResourceInfo` с аудиторией. Качество на новых ресурсах отдельно не проверялось.

Сравнение находится вне `src`: `python -m model_tests.compare_social_metrics`. Выбор производится по среднему нормированному MSE CV трёх социальных метрик, чтобы масштаб просмотров не подавлял реакции и комментарии. Также сохраняются исходные MSE, RMSE, MAE, R², время обучения и прогноза, графики PNG/SVG.

На текущих 2415 статьях MLP лучшая среди четырёх обученных семейств; базовое среднее по каналу немного лучше по общему критерию CV. Поэтому преимущества над простым прогнозом среднего пока не подтверждены. Подробные значения и графики находятся в `model_tests/results/social_metrics_20261021_145508_UTC/`.

Метрики относятся к статьям возраста **2–14 дней на момент сбора**. Это не прогноз количества строго через два или четырнадцать дней. Случайное разделение по одинаковым текстам проверяет текущие каналы; для проверки будущих публикаций потребуется отдельная выборка более поздних дат.
