## Критерий выбора: точность и время ответа

С 11.11.2026 используются только два критерия: ошибка групповой CV и полный локальный ответ после загрузки моделей. Максимальный измеренный ответ должен быть не более **10 секунд**. В текущем подборе просмотры, реакции и комментарии выбираются независимо по MSE исходных количеств; каждая метрика должна улучшить среднее канала минимум на 2%. Средняя нормированная MSE остаётся в исторических сравнительных отчётах. Время обучения сохраняется в технических данных, но не участвует в выборе. Полный ответ включает E5 и регрессор, а для модуля 4 — также прогноз оценки текста. Измерения `response_time` включают тексты разной длины из обучающей части; сеть и БД не входят. В `single_prediction` и `batch_prediction` отдельно остаются времена только регрессоров. Измеренный предел описывает проверенные тексты и оборудование, а не гарантированную задержку любого запроса.

## Что сравнивается в модуле 3

| Модель | Код |
| --- | --- |
| Градиентный бустинг | `gradient_boosting`, HistGradientBoostingRegressor |
| Случайный лес | `random_forest`, RandomForestRegressor |
| CatBoost | `catboost`, CatBoostRegressor |
| Нейросеть | `neural_network`, PyTorch MLP `768 → 256 → 64 → 1` |

Вход одинаковый: 384 числа SBERT-вектора текста и 384 числа эмбеддинга темы. Цель — оценка второго модуля в `[-10, 10]`. SBERT заморожен, веса не обучаются. Дополнительно измеряется ошибка прогноза средним значением — это ориентир для оценки пользы моделей.

Выбранная текстовая нейросеть использует слои `256 → 128`, ReLU, Dropout 0.5 и выход `10 × tanh`. Оптимизатор AdamW, функция потерь MSE, 60 эпох, пакеты по 128, шаг 0.0005, weight decay 0.1. Масштабирование признаков обучается только внутри обучающей части каждого разбиения. При прогнозе Dropout отключён. Основное сравнение использует фиксированные параметры; отдельный подбор реализован в `tune_models.py`. Первые исторические отчёты использовали сеть с 100 эпохами и слоями `256 → 64`.

## Как устроена проверка

1. Нормализованные точные повторы текста объединяются в группы: Unicode NFKC, регистр, пробелы. Группа целиком попадает в одну часть.
2. 20% групп откладываются для финальной проверки. Остальные используются в трёх частях групповой перекрёстной проверки (CV).
3. У всех четырёх моделей одинаковые обучающие, валидационные и тестовые статьи. Каждая модель заново обучается в каждой части CV, затем один раз на всей обучающей части для финальной проверки.
4. Предлагаемая модель выбирается по среднему **MSE CV**. Отложенная проверка не участвует в выборе, остановке обучения или настройке параметров.
5. Все четыре обученные модели сохраняются. Окончательный выбор одной модели для проекта выполняется после анализа результатов; скрипт не удаляет остальные реализации и не меняет модель приложения автоматически.

Параметры CLI: `--seed 42`, `--folds 3`, `--test-size 0.2`, `--threads 4`, `--timing-repeats 9`, `--single-repeats 21`. Все эксперименты используют фиксированную `intfloat/multilingual-e5-small`. Флаг `--reembed` пересчитывает признаки локально той же моделью, без перезаписи векторов БД. Несовместимые или неизвестные векторы в БД предварительно пересчитываются командой `python -m src.database reembed`.

## Ошибка

```text
MSE  = mean((оценка_по_метрикам − прогноз)²)   # среднеквадратичная ошибка, баллы²
RMSE = sqrt(MSE)                             # корень MSE, баллы
```

Основной график показывает MSE. В таблицах также есть RMSE, MAE и R². Меньшая MSE лучше. Разброс CV на графике — стандартное отклонение между частями, не доверительный интервал. Если константный прогноз оказался лучше моделей по CV, это явно указывается в отчёте.

## Время выполнения

Измеряется реальное прошедшее время через `time.perf_counter()`. Модели запускаются последовательно на CPU с одинаковым лимитом потоков. В технических данных сохраняется время обучения на всей обучающей части (80% данных) и в частях CV. Оно не участвует в выборе модели.

Для прогнозирования измеряются:

- **Пакетный прогноз** для всей отложенной выборки: медиана нескольких прогонов, число статей и время на статью.
- **Прогноз одной статьи**: медиана отдельных вызовов. Это отдельное измерение, оно не равно времени пакета, поделённому на количество статей.
- **Полный ответ** (`response_time`): исходный текст проходит E5 и регрессор; для модуля 4 также прогнозируется оценка текста и все три социальные метрики. Восемь примеров выбираются из обучающей части по длине текста; сохраняются медиана, p95 и максимум.
- В JSON сохраняются все повторные замеры, среднее, медиана, стандартное отклонение и 95-й процентиль.

Перед замером выполняется прогрев. Пакетный и одиночный прогноз на готовых признаках измеряют только регрессор, включая scaler MLP, и исключают SBERT. Для выбора применяется полный `response_time`, который включает SBERT. Чтение БД, загрузка моделей, сеть, сохранение файлов и построение графиков в него не входят. Общая подготовка признаков и векторизация восьми текстов также измеряются отдельно. Машина и версии библиотек записываются в `report.json`. Нагрузка других программ может влиять на время.

Перефразированные близкие тексты могут оказаться в разных частях; группировка исключает нормализованные точные повторы.

Проверить весь собранный набор по точным границам окна и снимкам аудитории из
актуального отчёта `update`:

```powershell
.\.venv312\Scripts\python.exe -m model_tests.validate_collection model_tests/results/collection.json
```

Текущий отчёт имеет одинаковую структуру для одного или нескольких источников:
`selected_sources`, `sources`, объединённый `resources`, `limit_per_resource`.
Запись ресурса содержит `address`, `source`, метаданные `resource`, `window`,
счётчики и `details`. Валидация читает объединённый `resources`; её собственный
результат тоже содержит `resources` с полями `address` и `source`.
`CollectionResult` доступен только через `collector.last_result`; он сохраняет
счётчики и после частичной ошибки. Дополнительные показатели Telegram находятся
в `last_result.details`. PostgreSQL-проверки используют этот же контракт.

## Модуль 4: прогноз социальных метрик

```powershell
# Сравнить четыре семейства моделей на текущей БД
.\.venv312\Scripts\python.exe -m model_tests.compare_social_metrics

# Повторно построить графики по сохранённым результатам
.\.venv312\Scripts\python.exe -m model_tests.social_metric_plots model_tests/results/<каталог_запуска>

# Обучить рабочую пару: нейросеть модуля 3 + выбранная модель модуля 4
.\.venv312\Scripts\python.exe -m src.social_metrics_prediction train
```

Кандидаты модуля 4 находятся в `social_metric_candidates.py`: HistGradientBoosting, RandomForest, CatBoost и MLP. На каждую социальную метрику обучается свой регрессор; выбирается одно семейство для всех трёх. Дополнительно проверяется базовый прогноз среднего количества метрик на подписчика для каждого ресурса.

Входные признаки: категория темы, идентификатор ресурса, вид ресурса, прогноз оценки популярности, логарифм аудитории. Категории кодируются OneHotEncoder, обученным только на соответствующей обучающей части. Цели: `count / audience * 1000`. Обучающие наблюдения взвешиваются пропорционально квадрату аудитории: MSE этих целей тогда эквивалентен MSE абсолютных количеств (с точностью до общего множителя). Прогноз возвращается в абсолютные целые неотрицательные количества. Для обучения используется аудитория, сохранённая при замере конкретной статьи; для прогноза — аудитория ресурса.

**Проверка без утечки метрик.** Оценка модуля 2 вычисляется из целевых просмотров, реакций и комментариев. Поэтому подставлять её в признаки отложенной проверки нельзя: это означало бы заранее знать ответы. Используются прогнозы выбранной нейросети модуля 3. Для каждой строки обучения модуля 4 такой прогноз получен нейросетью, не видевшей её группы текстов. Внутри каждой CV-части cross-fitting повторяется заново; валидационная часть не попадает ни в одну обучающую процедуру. Для отложенной проверки нейросеть обучена только на 80% данных. Полные рабочие артефакты затем обучаются отдельно.

MSE измеряется для каждой социальной метрики в исходных количествах. Для выбора семейства средние квадраты ошибок делятся на дисперсию каждой метрики обучающей части, усредняются по трём метрикам и трём разбиениям. Так просмотры не получают больший вес из-за масштаба чисел. Сохраняются также RMSE, MAE, R², время обучения и время прогноза (пакет/одна статья, после прогрева).

Результаты сохраняются в новом `results/social_metrics_<дата>/`: `summary.md`, `report.json`, `metrics.csv`, `test_predictions.csv`, снимок признаков/целей, `inputs.json`, `splits.json`, четыре модели проверки, графики PNG/SVG. Времена SBERT и подготовки прогнозов модуля 3 указаны отдельно. `social_metric_plots.py` повторно строит графики без переобучения.

Параметры сравнения: `--output`, `--seed` (42), `--folds` (3), `--threads` (4), `--test-size` (0.2). `--prepared-run <каталог>` повторно использует прогнозы нейросети с проверкой совпадения данных и разбиения; заново обучаются только кандидаты модуля 4. Время общей подготовки при таком запуске берётся из исходного отчёта. Группы — нормализованные одинаковые тексты; приближённые перефразирования могут оказаться по разные стороны разбиения. Это проверка имеющихся Telegram-каналов, а не будущих дат/новых платформ. Метрики относятся к статьям возраста 2–14 дней, а не к фиксированному горизонту прогноза.

Производственный модуль не импортирует кандидатов или графики из `model_tests`. Альтернативные модели для старого модуля 3 тоже находятся здесь: `text_candidates.py`. Исторические артефакты можно открыть `ExperimentalTextAssessment.load(path)`.

Документация группового разделения: [scikit-learn](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data).
